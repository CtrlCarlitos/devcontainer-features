# Global Agent Skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install the identical curated skill roster globally for Claude Code, OpenCode, Antigravity IDE, Antigravity CLI, and Codex.

**Architecture:** `curated-skills` will use the `skills` CLI only to materialize a temporary canonical roster. The installer will then copy each staged skill into documented native discovery directories selected by the `agents` option. This avoids depending on the CLI's agent mappings, particularly its Codex mapping.

**Tech Stack:** Dev Container Features, Bash, `npx skills`, Dev Container feature test framework.

**Spec:** `docs/superpowers/specs/2026-09-15-global-agent-skills-design.md`

## Global Constraints

- Default `agents` value: `claude-code,opencode,antigravity,codex`.
- Claude Code target: `$REMOTE_USER_HOME/.claude/skills`.
- OpenCode target: `$REMOTE_USER_HOME/.config/opencode/skills`.
- Antigravity target: both `$REMOTE_USER_HOME/.gemini/antigravity/skills` and `$REMOTE_USER_HOME/.gemini/antigravity-cli/skills`.
- Codex target: `$REMOTE_USER_HOME/.agents/skills`.
- Install every requested skill into every selected target; fail instead of silently omitting a selected target.
- Preserve explicit `agents` subsets; `antigravity` always means both native Antigravity targets.
- Do not add Serena, Graft, or Guardrail integration in this change.

---

## File Structure

- `src/curated-skills/devcontainer-feature.json`: exposes the four-agent default and accurate option documentation.
- `src/curated-skills/install.sh`: stages skills once, validates them, copies them to native target directories, and sets ownership only on installed skill directories.
- `test/curated-skills/default.sh`: asserts the complete default roster exists and is remote-user-owned in all five native target trees.
- `test/curated-skills/single-skill.sh`: asserts a custom one-skill roster is copied to all default targets and no target receives an extra skill.
- `test/curated-skills/claude-only.sh`: confirms an explicit subset installs only into Claude Code's native target.
- `test/curated-skills/scenarios.json`: remains the scenario definition source; update only if test naming/inputs must change.

### Task 2: Stage And Distribute The Curated Roster

**Files:**
- Modify: `src/curated-skills/install.sh:6-156`
- Modify: `src/curated-skills/devcontainer-feature.json:3-17`

**Interfaces:**
- Consumes: `SKILLS`, `AGENTS`, `_REMOTE_USER`, and `_REMOTE_USER_HOME`.
- Produces: a complete copied roster in every selected native target; invalid
  agent names and missing staged skills exit non-zero.

- [ ] **Step 1: Add a target resolver after parsing `AGENTS`**

Replace `AGENT_FLAGS` construction with a `TARGET_DIRS` array populated by a
validated `case` expression:

```bash
case "$agent" in
    claude-code) TARGET_DIRS+=("$REMOTE_USER_HOME/.claude/skills") ;;
    opencode) TARGET_DIRS+=("$REMOTE_USER_HOME/.config/opencode/skills") ;;
    antigravity)
        TARGET_DIRS+=(
            "$REMOTE_USER_HOME/.gemini/antigravity/skills"
            "$REMOTE_USER_HOME/.gemini/antigravity-cli/skills"
        )
        ;;
    codex) TARGET_DIRS+=("$REMOTE_USER_HOME/.agents/skills") ;;
    *) echo "ERROR: unsupported agent '$agent'"; exit 1 ;;
esac
```

Deduplicate `TARGET_DIRS` before copying so a repeated agent option cannot
cause repeated writes.

- [ ] **Step 2: Make the existing tests pass with a temporary staged roster**

Create a temporary directory and cleanup trap before invoking `npx`:

```bash
STAGING_HOME="$(mktemp -d)"
trap 'rm -rf "$STAGING_HOME"' EXIT
STAGED_SKILLS="$STAGING_HOME/.claude/skills"
```

For both ordinary and renamed skills, invoke `skills@latest add` with
`HOME="$STAGING_HOME"`, only `-a claude-code`, `-g -y --copy`, and the
existing noninteractive stdin redirection. This makes
`$STAGED_SKILLS/<skill>/SKILL.md` the single canonical roster regardless of
the selected output agents.

After all source installs, fail if no staged `SKILL.md` exists. For each
staged skill directory, verify its `SKILL.md`, then for every `TARGET_DIRS`
entry create the directory, replace only the same-named target skill
directory, and copy the staged directory with `cp -a`.

For a root build with a non-root remote user, run `chown -R` only on each
copied target skill directory. Do not recursively change ownership of an
entire pre-existing agent configuration tree.
